# Terminology Registry

## Purpose
Canonical source of truth for product terms, feature names, UI labels, and domain vocabulary used across all prototype pages, microcopy, navigation items, and documentation.

Prevents terminology drift — where the same concept gets three different names across three pages.

## Ownership
UX Writing / Product Design

## Status
Active — updated as new terms are identified or deprecated

## Update Rules
- Add a term when it appears in a new page, nav item, or feature for the first time
- Do not add terms that are generic English words without product-specific meaning
- Mark terms as `Deprecated` before removing — never delete without a replacement entry
- All changes require review before being applied to existing pages

## Entry Template
```markdown
### [Term]
**Preferred form:** [exact casing and spelling]
**Category:** [UI label / feature name / domain entity / action verb / status / navigation]
**Definition:** [what it means in this product]
**Usage context:** [where it appears]
**Do not use:** [alternative forms to avoid]
**Rationale:** [why this form was chosen]
**Status:** Active / Deprecated
**Added:** [YYYY-MM-DD]
**Last reviewed:** [YYYY-MM-DD]
```

## Review Requirements
- Any new feature or page must register its primary terms before shipping
- Terms appearing in navigation must match the sidebar label exactly
- Status chip labels must be consistent with their domain type entry here
