# ADR-002: SCSS Token System — No Inline Styles

## Status
Accepted

## Context
Rapid prototyping creates pressure to use inline styles or hardcoded values to move quickly. This creates visual inconsistency when the design system evolves and makes global updates impossible.

## Decision
All visual values (color, spacing, typography, radius, shadows, transitions) must use SCSS tokens defined in `src/styles/_variables.scss`.

Rules:
- No `style={{ }}` props in JSX
- No hardcoded hex colors in component SCSS files
- No hardcoded px values for spacing, font-size, radius, or shadow when a token exists
- New tokens may only be added to `_variables.scss` — never inline in a component
- CSS custom properties (`var(--x)`) are permitted only to bridge SCSS tokens into SVG attributes (e.g. `fill="var(--token)"`)

## Consequences
- Global theme changes require editing one file
- All components automatically inherit future design token updates
- Slight friction when a token does not yet exist — must add to `_variables.scss` or report a DS gap

## Alternatives Considered
- CSS Modules with hardcoded values: rejected — no global token control
- Tailwind utility classes: rejected — does not integrate with the existing SCSS token system
